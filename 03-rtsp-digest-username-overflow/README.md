# [CVE-TBD] D-Link DCS-6501LH V3.03.02 Unauthenticated Stack Buffer Overflow in RTSP Digest Authentication

## VulDB Submission Fields

- Vendor: D-Link
- Product: DCS-6501LH (DCS6501LHCx)
- Version or Commit: V3.03.02 (firmware package DCS6501LHCx_FW303B02_SD)
- Vulnerability: Stack-based Buffer Overflow (CWE-121)
- Advisory / Exploit URL: https://github.com/Zimo-666/D-Link-DCS-6501LH-cves/tree/main/03-rtsp-digest-username-overflow
- Description:

```
A stack-based buffer overflow vulnerability was discovered in D-Link
DCS-6501LH camera firmware v3.03.02. ValidateAuthorizationHeader in the
aoni_ipc RTSP server copies the username value of a Digest Authorization
header into an 80-byte stack buffer with strncpy(), using the distance to
the next double quote as the length without any bound. The stack frame is
512 bytes; the destination is 348 bytes below the saved return address, so
a username longer than 348 bytes overwrites the saved registers and the
return address, and the header is parsed before any password comparison, so
no valid credentials are needed. Reproduction: send the TEARDOWN request
generated by poc.py to an existing RTSP session (the built-in echoshow
session created at startup) with a 400-byte Digest username; the daemon
crashes with pc = ra = 0x41414141 in an emulated run of the stock binary,
which proves control of the instruction pointer. Impact: unauthenticated
remote code execution in the RTSP daemon (running as root), demonstrated as
instruction-pointer control with a crash-only payload; the same request with
a short username returns 401 Unauthorized and leaves the service running.
Proposed CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H (8.8).
```

---

## Technical Disclosure

### Summary

`ValidateAuthorizationHeader` (address `0x004F5FC8` in `aoni_ipc`) parses the
Digest `Authorization` header of RTSP requests. The `username` value is copied
with `strncpy()` into a fixed 80-byte stack buffer, and the copy length is the
distance between the opening quote and the next double quote in the
attacker-supplied header. There is no upper bound and the buffer is positioned
348 bytes below the saved return address, so a long username overwrites the
saved registers and the return address. Parsing happens before any password
comparison, so the request does not need valid credentials.

### Affected Product and Firmware

- Vendor: D-Link
- Product: DCS-6501LH (DCS6501LHCx), indoor network camera
- Firmware: V3.03.02, package `DCS6501LHCx_FW303B02_SD.bin`
  (image 16,025,960 bytes, sha256
  `8751e1219ddfd839f59a3b01b2ecace2ecf3c9b95cc83f8278886bc87e0652c1`)
- Application build: `AONI_IPC Make On Aug  4 2025 18:08:26 V3.03.02`
- Platform: Ingenic T31, MIPS32 little-endian, Linux 3.10.14

### Vulnerability Details and Root Cause

Prologue of the vulnerable function:

```
004f5fc8:  addiu sp,sp,-512
004f5fe0:  sw    ra,508(sp)
004f5fec:  sw    s7,504(sp)   ... s0 at 476(sp)
```

Stack buffers: `v33[128]` at `sp+32`, `dest[80]` at `sp+160`, `v35[80]` at
`sp+240`, `v36[80]` at `sp+320`, `v37[76]` at `sp+400`.

Username handling:

```c
v4 = strstr(RequestMsgHeader, "username");
v5 = v4 + 10;
if (v4) {
    v6 = strchr(v4 + 10, '"');
    if (!v6)
        return 401;
    v7 = 0;
    strncpy(dest, v5, v6 - v5);   /* dest[80], length from the header */
}
```

With the destination at `sp+160` and `ra` at `sp+508`, any username longer than
348 bytes overwrites the saved return address; 352 bytes already crash the
daemon, and 400 bytes of `A` produce `pc = ra = 0x41414141`.

The same function contains a second instance of the same defect: the `nonce`
value is copied with `memcpy(v35, v18, v19 - v18)` into the 80-byte `v35`
buffer at `sp+240`, again with a length derived from the header.

### Vulnerable Component, Function and Call Chain

- Component: RTSP server in `aoni_ipc`
- Entry: `RTSPTeardownHandle` (`0x004F6624`) -> `ValidateAuthorizationHeader`
  (`0x004F5FC8`), unbounded copy to `dest` (stack, `sp+160`)
- Session: the built-in `echoshow` session (`rtsp://<host>/live/echoshow/video`)
  is created at startup and returns a Digest challenge to unauthenticated
  clients, which is enough to reach the vulnerable code.

### Authentication Requirements and Attack Conditions

- No valid credentials: the overflow occurs while the credentials are parsed,
  before the password comparison.
- Network reachability to TCP port 554 is required; the session path
  `live/echoshow/video` is fixed in the firmware.
- No user interaction and no configuration change are required.

### Proof of Concept and Reproduction

The PoC is `poc.py` in this directory. It sends a control request with a short
username and then a request with a 400-byte username:

```bash
python3 poc.py <host> [port]
```

Expected result on a vulnerable device: the control request returns
`401 Unauthorized` and the service stays up; the oversized request gets no
response and the RTSP daemon crashes with the instruction pointer set to
`0x41414141`.

Observed in an emulated environment with the stock binary (GDB attached to the
QEMU guest):

```
Thread 2 received signal SIGSEGV, Segmentation fault.
0x41414141 in ?? ()
pc: 0x41414141   ra: 0x41414141
s0: 0x41414141   s1: 0x41414141
```

### Observed Results and Evidence

Length sweep against a freshly started instance (TEARDOWN to the echoshow
session, no credentials):

| username length | response | process |
|---|---|---|
| 5 to 320 | `401 Unauthorized` | alive |
| 340 | `401 Unauthorized` | SIGSEGV after the response (saved `s6` corrupted) |
| 352 | none | SIGSEGV (saved `ra` overwritten) |
| 400 | none | SIGSEGV, `pc = ra = 0x41414141` |

The register values equal the fill byte of the username, which demonstrates
direct control of the saved return address and therefore of the instruction
pointer.

### Security Impact

Unauthenticated remote code execution potential. The RTSP daemon runs as root
on the device and this build has no stack canary in the affected function, so a
crafted username can redirect execution. The PoC intentionally uses a
crash-only payload (a remote denial of service); code execution was not
demonstrated beyond instruction-pointer control.

### CWE and CVSS

- CWE-121: Stack-based Buffer Overflow
- CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H (8.8)

The score reflects demonstrated instruction-pointer control from an
unauthenticated network request on the local network; 9.8 applies if port 554
is reachable from the internet.

### Related CVEs and Novelty

The public issues for this firmware version are CVE-2026-125079 (hard-coded
credentials in `SystemConfig.ini`) and CVE-2026-113735 (weak credential in
`mydlink_set_root_pwd`); both concern credential values and neither involves
memory corruption. Two other memory-safety issues were reported separately for
this product: a heap overflow in the RTSP request parser
(`RTSPServerParseMessage`, missing header-count bound) and an invalid free of
the Digest `uri` pointer (`ValidateAuthorizationHeader`, free of a non-heap
pointer). This issue is a different root cause (unbounded copy of the
`username` value into a fixed stack buffer) with a different fix, so it is
reported separately.

### Suggested Remediation

- Bound the username copy to `sizeof(dest) - 1` and always NUL-terminate.
- Apply the same bound to the `nonce` copy and to any other header value copied
  into a fixed buffer in this function.
- Reject Digest headers whose fields exceed protocol limits with
  `400 Bad Request`.
- Build the daemon with stack protector and fortify sources enabled.
