# [CVE-TBD] D-Link DCS-6501LH V3.03.02 Unauthenticated Stack Buffer Overflow in the StreamProxy HTTP Handler

## VulDB Submission Fields

- Vendor: D-Link
- Product: DCS-6501LH (DCS6501LHCx)
- Version or Commit: V3.03.02 (firmware package DCS6501LHCx_FW303B02_SD)
- Vulnerability: Stack-based Buffer Overflow (CWE-121)
- Advisory / Exploit URL: https://github.com/Zimo-666/D-Link-DCS-6501LH-cves/tree/main/04-streamproxy-content-length-body-overflow
- Description:

```
A stack-based buffer overflow vulnerability was discovered in D-Link DCS-6501LH camera firmware v3.03.02. The mydlink StreamProxy service that starts during normal boot listens on TCP port 7000 in plaintext; its per-client handler ExecuteOneAccept (0x004A38FC in aoni_ipc) reads an HTTP request, parses the Content-Length header and copies that many bytes into a 1024-byte stack buffer, validating only that the value is below 5121. The stack frame is 3168 bytes, the destination buffer is at sp+2088 and the saved return address at sp+3164, only 1076 bytes above it, so any Content-Length above 1076 overwrites saved registers and the return address, and no authentication is involved. Reproduction: send the POST request generated by poc.py (Content-Length 4000 with a 1500-byte body) to port 7000; the daemon crashes with pc = ra = 0x41414141 in an emulated run of the stock binary, proving control of the instruction pointer, while a Content-Length of 64 leaves the service running. Impact: unauthenticated remote code execution in the camera daemon running as root, demonstrated as instruction-pointer control with a crash-only payload. Proposed CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H (8.8).
```

## Technical Disclosure

### Summary

The device starts a mydlink StreamProxy listener on TCP port 7000 during the
normal boot sequence (`pf_mydlink_init` -> `mydlink_StreamProxyLib_StartServer`).
The listener speaks plaintext HTTP and hands each connection to
`ExecuteOneAccept`. That function parses `Content-Length` from the request and
performs a `memcpy` of the declared size into a fixed 1024-byte stack buffer,
with the only sanity check being that the value is below 5121. Because the
saved return address sits 1076 bytes above the buffer, a moderate
`Content-Length` overwrites it and the attacker controls the instruction
pointer.

### Affected Product and Firmware

- Vendor: D-Link
- Product: DCS-6501LH (DCS6501LHCx), indoor network camera
- Firmware: V3.03.02, package `DCS6501LHCx_FW303B02_SD.bin`
  (image 16,025,960 bytes, sha256
  `8751e1219ddfd839f59a3b01b2ecace2ecf3c9b95cc83f8278886bc87e0652c1`)
- Application build: `AONI_IPC Make On Aug  4 2025 18:08:26 V3.03.02`
- Platform: Ingenic T31, MIPS32 little-endian, Linux 3.10.14

### Vulnerability Details and Root Cause

`ExecuteOneAccept` at `0x004A38FC`:

```c
char s[2048];        /* request, recv() limited to 0x7FF bytes */
char dest[1024];
...
v10 = recv(*v2, s, 0x7FFu, 0);
if ((unsigned int)(v10 - 1) < 0x7FF) {
    s[v10] = 0;
    if (strstr(s, "POST")) {
        ...
        v14 = strstr(s, "Content-Length");
        v15 = strstr(s, "\r\n\r\n");
        strncpy(nptr, v14 + 16, v16 - 16 - v17);   /* digits */
        v18 = strtol(nptr, 0, 10);                 /* attacker value */
        if (v18 >= 5121)
            puts("content len is too long");
        else
            memcpy(dest, &v14[v19 + 20], v18);     /* dest[1024] */
    }
}
```

Prologue:

```
004a38fc:  addiu sp,sp,-3168
004a3920:  sw    ra,3164(sp)
```

`dest` is at `sp+2088`; the saved return address is at `sp+3164`, i.e. 1076
bytes above the start of the buffer. Any `Content-Length` in 1077..5120 is
accepted and overwrites `s0..s4` and `ra`. The `Content-Type` branch contains
the same defect with `strncpy(dest, &s[v10 - Contentlen], Contentlen)`.

### Vulnerable Component, Function and Call Chain

- Component: mydlink StreamProxy in `aoni_ipc`
- Listener: `HttpServer_FUN` (`0x004A34B8`) binds TCP 7000
  (`strcpy(addr.sa_data, "\x1BX")` = 0x1B58) and spawns `ExecuteOneAccept`
- Fault: `memcpy` of attacker-controlled `Content-Length` into `dest[1024]`
  at `0x004A3BFC`
- Start condition: default boot path (`pf_mydlink_init`)

### Authentication Requirements and Attack Conditions

- No authentication: the listener is plaintext HTTP and the vulnerable copy
  happens before any credential handling.
- Network reachability to TCP port 7000; local network by default, internet if
  the port is forwarded.
- No user interaction and no configuration change are required.

### Proof of Concept and Reproduction

The PoC is `poc.py` in this directory. It sends a control request with
`Content-Length: 64` and then the trigger with `Content-Length: 4000` and a
1500-byte body:

```bash
python3 poc.py <host> [port]
```

Expected result on a vulnerable device: both connections are closed without an
HTTP response (the handler only answers a specific command), the control leaves
the daemon running, and the trigger crashes it with the instruction pointer set
to `0x41414141`.

Observed under GDB in an emulated environment with the stock binary:

```
Thread 2 received signal SIGSEGV, Segmentation fault.
#0  0x41414141 in ?? ()
pc: 0x41414141   ra: 0x41414141
```

### Observed Results and Evidence

| Content-Length | body | result |
|---|---|---|
| 64 | 16 bytes | connection reset, process alive |
| 1024 | 16 bytes | connection reset, process alive |
| 2000 | 16 bytes | connection reset, process dead (SIGSEGV) |
| 4000 | 16 bytes | connection reset, process dead (SIGSEGV) |
| 4000 | 1500 bytes of `A` | SIGSEGV with `pc = ra = 0x41414141` |

The body fill lands on the saved return address, which demonstrates direct
control of the instruction pointer.

### Security Impact

Unauthenticated remote code execution potential: the daemon runs as root, the
affected frame has no stack canary, and the attacker controls both the
overwritten return address and the adjacent saved registers. The provided PoC
is a crash-only demonstration of control-flow hijacking; no shell was spawned.

### CWE and CVSS

- CWE-121: Stack-based Buffer Overflow
- CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H (8.8)

### Related CVEs and Novelty

The published issues for this firmware version are CVE-2026-125079 (hard-coded
credentials in `SystemConfig.ini`) and CVE-2026-113735 (weak credential in
`mydlink_set_root_pwd`), both unrelated to memory safety. Three other
memory-safety issues were reported separately for this product: a heap overflow
in the RTSP request parser, an invalid free in RTSP digest handling, and a
stack overflow in the RTSP digest `username` copy. This issue is in a different
component (mydlink StreamProxy, port 7000), on a different network protocol
(plaintext HTTP POST), with an independent root cause (Content-Length not
checked against the destination size) and an independent fix.

### Suggested Remediation

- Reject `Content-Length` values larger than the destination buffer minus one,
  and cap the body size at the protocol layer.
- Replace the fixed stack buffer with a heap buffer sized from the validated
  length (bounded by a hard maximum), or stream the body.
- Apply the same bound to the `Content-Type` branch.
- Build with stack protector and fortify sources enabled.
